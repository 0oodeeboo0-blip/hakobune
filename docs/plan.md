# Hakobune 開発計画

最終更新: 2026-11-06

## 目指すもの

FFFTP で慣れた左右 2 画面の使い方はそのままに、次の 3 つを実現する。

1. **確実に届く**: 一覧が消えない。黙って後回しにしない。止まっても続きから再開できる。
2. **今どきの見た目**: Windows 11 と同じデザイン。ダークモードに対応し、高解像度の画面でもくっきり見える。
3. **乗り換えやすい**: FFFTP の接続先の設定を読み込める。保存済みのパスワードも、マスターパスワードがあれば取り込む。

## 決まっていること

| 項目 | 決定 |
|---|---|
| 名前 | Hakobune |
| 公開 | GitHub で公開する（MIT License） |
| 対応する通信方式 | FTP、FTPS（明示・暗黙）、SFTP |
| 画面の言語 | 日本語（英語版は後で） |
| 対象の Windows | Windows 11（Windows 10 1809 以降でも動く） |
| 技術 | C# / .NET 10、WinUI 3（Windows App SDK 2.x）、FluentFTP、SSH.NET |

## 機能

### 最初の版（v1.0）

- **接続**: FTP、FTPS、SFTP。接続先をフォルダで整理できる。クイック接続。
- **画面**: パソコン側とサーバー側の 2 画面、階層をたどれるパス表示、絞り込み・検索・並べ替え、フォルダ同時移動、ブックマーク、エクスプローラーとのドラッグ＆ドロップ。
- **ファイル操作**: 削除、名前変更、フォルダ作成、属性変更（chmod）、任意のコマンド。
- **転送**: 並列転送、自動でのやり直しと途中からの再開、転送後の照合（サイズ。対応サーバーではハッシュも）、同名ファイルの扱い（上書き／新しければ上書き／飛ばす／名前を変える／確認する）。
- **安全**: パスワードは Windows の資格情報マネージャーに保存。初めて接続するサーバーは鍵や証明書を確認。暗号化されていない接続には警告。
- **その他**: 色分けしたログ（コピー・保存できる）、完了の通知、タスクバーの進捗表示、FFFTP と同じショートカットキー、日本語ファイル名の文字コード（UTF-8／Shift_JIS／EUC-JP）。

### その後の版

差分を確認してから実行するミラーリング、フォルダの比較、タブでの複数接続、プロキシ、ファイル内容の文字コード変換、英語版、自動アップデート。

### 引き継がないもの

ダイヤルアップ接続、ワンタイムパスワードの計算、古い特殊なサーバー種別への対応。

## 転送の仕組み（FFFTP の問題への対処）

| FFFTP の問題 | Hakobune での対処 |
|---|---|
| 画面の操作と転送が 1 本の接続を取り合う | 画面用と転送用の接続を必ず分ける。1 本の接続を同時に複数の場所から使わない |
| 壊れた接続を使い続ける | エラーが出た接続はすぐ捨てて、つなぎ直す。何もしていない間も接続を保つ |
| 一覧を取り直せないと、一覧が消える | 前の一覧を残したまま「更新に失敗、やり直し中」と表示し、自動で取り直す |
| 失敗したファイルを最後に回し、何度でも繰り返す | 一時的なエラーは、少し待ってその場で数回やり直し、途中から続きを送る。権限エラーのように直らないものはやり直さず、理由と一緒に「失敗」にする |
| エラーのダイアログで転送が全部止まる | 止めない。確認が必要なファイルは一覧に集めて、ほかの転送は続ける。最後に結果を出し、失敗した分だけ送り直せる |
| 届いたかどうか確かめない | 送った後にサイズを照合する（できれば中身も） |
| サーバーの同時接続数の上限に引っかかる | 断られたら、同時に送る数を自動で減らす |
| アプリが落ちると、送信待ちが消える | 送信待ちを保存しておき、再起動後に続きから再開する |

失敗の分類は `Hakobune.Core.Transfers.FtpReplyClassifier`、やり直しの決まりは `RetryPolicy` にある。

## 見た目

- Windows 11 の標準デザイン（Fluent）。背景は Mica。Windows の設定に合わせてライトとダークが切り替わる。
- ボタンのアイコンは Fluent System Icons（MIT）。ファイルの種類のアイコンはエクスプローラーと同じものを使う。
- 配置: 左に接続先の一覧（たためる）、中央に 2 画面、下に送信待ちの一覧（進行中・待機中・完了・失敗）、上に接続の状態（暗号化されていれば鍵マーク）。
- 文字は Yu Gothic UI。FFFTP より大きめで行間もゆったりさせる。
- アクセント色は青緑（#0B6E78、ダークでは明るめ）。舟と水の名前に合い、Windows 標準の青とも区別できる。状態は色だけでなくアイコンと文字でも示す。
- 行の高さは「標準」（34px）を既定にし、設定で「コンパクト」（28px）にも切り替えられる。
- 接続先の一覧は最初は開いた状態で、たためる。
- デザイン案は claude.ai の Artifact で作り、確認してもらってから実装する（見た目・機能・使い勝手の判断は任せてもらっている）。

## 品質の確かめ方

- よく使われるサーバー（vsftpd、Pure-FTPd、ProFTPD、OpenSSH）を相手に、FTP・FTPS・SFTP を自動テストする。
- 回線を切る・遅くする・応答を止める、数千ファイル、深いフォルダ、巨大なファイル、日本語ファイル名（UTF-8／Shift_JIS）でも試す。
- ライトとダーク、表示倍率 100〜200% の画面写真で見た目を確かめる。
- 変更のたびに GitHub Actions でビルドとテストを回す。

## 進め方

| 段階 | 内容 |
|---|---|
| 0. 準備 | リポジトリと自動ビルドの用意、画面デザイン案 |
| 1. 転送の仕組み | 接続、一覧、送信待ち、やり直し、続きからの再開、照合と、その自動テスト |
| 2. 基本の画面 | 2 画面での閲覧、接続先の管理、送信待ちの一覧、ログ、ダークモード |
| 3. 普段使いできる版 | 変わったファイルだけ送る（同期）、送らないファイル、FFFTP の設定の読み込み、通知、配布と新しい版のお知らせ、上書き前の控えと「元に戻す」、ショートカット |
| 4. 機能の追加 | ミラーリング、フォルダの比較、タブ、プロキシなど |
| 5. 公開 | 署名、配布、ヘルプ、英語版 |

それぞれの段階の終わりに動くものを確認してもらってから、次へ進む。

### 進み具合

- **段階 0（完了）**: リポジトリ、CI（Linux でエンジンのテスト、Windows でアプリのビルド・起動テスト・画面写真）、メイン画面のデザイン案。
- **段階 1（完了）**: 送信待ちとやり直し（`TransferScheduler`）、FTP / FTPS（`FtpRemoteSession`）、SFTP（`SftpRemoteSession`）、送信待ちの保存（`TransferQueueFile`）、画面用の接続（`RemoteBrowser`）。
  偽のサーバーでのテストに加え、vsftpd・Pure-FTPd・ProFTPD・OpenSSH を相手に、接続をわざと切りながら 400 ファイルが全部届くことを CI で確かめている。
- **段階 2（完了。2026-11-07 に確認してもらった）**: 基本の画面。進め方と決めたことは [ui-plan.md](ui-plan.md)。
  2 画面（パソコン・サーバー）、接続先の管理とクイック接続、鍵と証明書の確認、送信待ちの一覧（一時停止・取り消し・送り直し・次回へ引き継ぎ）、
  アップロード・ダウンロード（ボタン・ドラッグ＆ドロップ・エクスプローラーから。空のフォルダも）、新しいフォルダ・名前の変更・削除・属性の変更、
  ログ（通信の詳細つき）、設定（ライト・ダーク、コンパクト、隠しファイル）、前回の画面の様子に戻すこと。
  CI では、Windows の上の FTP サーバーへアプリから実際に送って中身を照合し、画面写真も撮っている。
  確認でもらった声への対応: 方式の既定を「自動」にした（ロリポップ！が「明示的」でないと入れなかったため）、
  一覧を取り直したときに行が拡大・縮小する動きをやめ、増えた・変わった行だけをそっと光らせるようにした（3 案から選んでもらった「案B」）。
  段階 3 へ回したもの: 一覧の列の幅の変更、サーバーからエクスプローラーへのドラッグ、表示倍率 100〜200% の確認。
- **段階 3（作っているところ）**: 2026-11-07 に、追加機能の案から 1〜6 を選んでもらった（同期、送らないファイル、FFFTP の読み込み、通知、配布と更新のお知らせ、控えと元に戻す）。
  先に動く見本（claude.ai の「段階 3 の見本」）を見てもらい、「すすめて」をもらった。ブラウザで開く・その場で編集・左右の同時移動は段階 4 へ。
  作る順番は、送らないファイル → 同期 → 控えと元に戻す → FFFTP の読み込み → 通知 → 配布と更新のお知らせ（同期は送らないファイルの決まりを使う）。
  - 送らないファイル: できた（設定、接続先ごとの名前、パソコン側の一覧の印、設定の画面での試し）。
  - 同期: できた（比べ方は docs/ui-plan.md。実サーバー 4 種で「送った直後は何も送らない」「変えたものだけ送り、消したものだけ消す」を確かめている）。
    途中で、MLST の無いサーバー（vsftpd）でフォルダを見分けられない不具合を見つけて直した（`IRemoteSession.DirectoryExistsAsync`）。
  - 控えと元に戻す: できた（上書き・削除の前の控え、下の「控え」、元に戻す。実サーバー 4 種で、控えの中身と元に戻せることを確かめている）。
  - 使っていて出た声「複数のファイルをマウスで囲んで選びたい」: できた（エクスプローラーと同じ動き。CI で本物のマウスの操作で確かめている）。
  - 通知とタスクバー: できた（FFFTP の読み込みの調べ物を待つあいだに、順番を入れ替えて先に作った。設定の「お知らせ」で切れる）。
  - 配布と更新のお知らせ: できた（タグで Releases に置く仕組みと、ステータスバーの知らせ）。最初の Releases（v0.3.0）は、段階 3 を確認してもらうときに出す。
    あわせて、ダイアログの中身が高すぎると下が切れて送れなかったのを直した（設定・接続先の「詳しい設定」・同期の確認）。

## 参考: FFFTP の調査で分かったこと

FFFTP 5.8（master c0347d1）のコードで確認した。

- **アップロード後に一覧が空白になる**: 一覧の取り直しに失敗すると、表示中の一覧を全部消す（filelist.cpp:582-611）。さらに、受信が一度タイムアウトや中止になった接続は、その後の受信がすべて即失敗する（socket.cpp:204-222, 492-527）。接続のチェックは null かどうかしか見ないので、F5 では直らない（socket.cpp:683-687）。
- **後回しになる**: 転送に失敗したファイルを、送信待ちの最後に積み直す。回数の上限はない（getput.cpp:190-203, 1347-1388）。初期設定ではエラーのダイアログが出ている間、転送全体が止まる。
- **接続の取り合い**: 「メインウィンドウのソケットを再利用」が既定で ON。転送中かどうかの判定は待ち行列しか見ないため、最後の 1 件の転送中に画面の操作が同じ接続へ割り込む（getput.cpp:269-272, 389）。
